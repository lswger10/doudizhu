## 当前版本：活跃留座与安全接管（MCP 1.3，2026-09-07）

基于 `codex/tidal-entertainment` 的 `935e4b7`，仅修改斗地主裁判、MCP 和服务器生命周期。
发布 SHA、线上验证范围记入交付档案；本节定义当前代码契约，下方 1.2/更早版本为历史。

### 状态归属与身份边界

- `DoudizhuService` 仍是唯一裁判。席位归属与控制凭据分开：席位随真实活动保留，
  `lease_id` 只授权当前控制实例；替换控制端不重建比赛、不改分数、不接管其他玩家。
- `join_table(instance_id: UUID)` 使用 ChatGPT 工具调用的 `_meta[openai/subject]` 和
  `_meta[openai/organization]` 派生 owner，`_meta[openai/session]` 派生会话标识。
  只保存摘要，不输出平台原始标识。工具参数不能自报 owner/session/seat。
  每个新回复/控制实例生成新 instance_id，重试同一次 join 时复用它。
- 该信任只成立于现有 **同容器 loopback + OpenAI Secure MCP Tunnel** 边界。
  元数据不是独立签名凭证；不得把此端口公开、转发给任意客户端或依靠它抵御容器内恶意进程。
  缺少平台 subject/session 时拒绝入座与接管，不能降级为信任模型自报身份。
  [平台元数据定义](https://developers.openai.com/plugins/reference)；
  [隧道与关联组织范围](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)。

### 生命周期

1. 空座入座返回 joined；同实例重试返回 already_joined 和原凭据，处理入座回执丢失。
2. 读牌、出牌、等事件、互动以及官端牌桌的真实浏览器操作刷新活动时间。
   没有十分钟或其他总时长上限；round_end、match_end、回大厅、Chat 回复结束都不自动离席。
   单次事件等待仍最多 15 秒；持续等待保留席位，**不会自动唤醒已结束的 Chat 回复**。
3. 控制端最近 120 秒内有请求，或仍有待完成的事件等待时，新实例返回
   `controller_active + retry_after_ms`，不发凭据、不延长旧实例活跃时间。120 秒是失联判定窗口，
   不是总游戏时限，也不能证明网络另一端的进程已退出；暂停超过窗口的旧实例会被隔离。
4. 旧控制端超过保护窗口后，同 owner 的新会话/实例可直接 join 恢复，无需旧 lease。
   新凭据替换旧凭据，所有旧读牌、出牌、互动、离席调用被拒绝；并发恢复只允许一个获胜。
   恢复后必须 read_turn 读取当前比赛/回合，禁止重放旧动作。不同 owner 无法恢复保留中的席位。
5. 完全无真实活动 30 分钟后释放并停止未完成的官端场。裁判代打、AI 自动聊天、广播及
   WebSocket 心跳不续席，避免无人桌自己无限续命。席位计时与控制端保护计时互不替代。
   用户的“停止整场游戏”和官端 leave_table 明确释放；普通局间返回大厅继续留座。
6. 最后一个浏览器断线不再直接停止官端比赛；无浏览器时沿用禁止付费模型调用的检查。
   官端请求与裁判可继续；缺席玩家仍按原回合时限代打，不提供断网期间冻结牌局的保证。

席位 owner/会话摘要、实例、最后活动时间和本场互动回执进入现有私有 state.json（0600），
不进入浏览器快照或牌谱；lease_id 仅存在内存，不落盘。服务重启保留比赛和席位归属，
旧凭据失效，同 owner 可重新 join；互动回执保留，避免接管后重复扣道具。
单实例部署仍是前提，不新增数据库、服务、缓存、依赖或 Gateway/Relay 人格副本。
旧版未保存身份的遗留官端场无法安全归属，升级时按旧停止规则结束；部署前先结束旧牌局。

验证入口：`npm test` 新增 `scripts/test-seat-lifecycle.js`，用可控时钟模拟 25 小时活动，
由真实裁判完成四局、下一场、恢复与服务重启；另测真实 MCP HTTP 并发接管、身份缺失/不符、
旧控制端失效与互动幂等。`scripts/test-game-ui.js` 实测最后浏览器断开保留比赛，明确停止释放。
可控时钟验证不等于线上已经连续实玩 25 小时；线上平台身份透传仍须以实际工具回执验收。

部署沿用现有 TEST next-doudizhu 与隧道，需刷新 ChatGPT 应用的 join_table 参数。
回滚目标为 `935e4b7` 镜像：先结束游戏、备份并保留 `/data/doudizhu`，再回滚并刷新工具。
无数据库 migration；旧版不认识新增席位记录，会按旧规则停止官端场，不保留此版恢复能力。

### MCP 1.2 契约与维护

牌桌广播变化即返回。它等待在裁判操作队列之外，不阻塞其他玩家。cursor 只是
进程内变化标记，不复制牌局；客户端取消会移除等待监听，同一席位只允许一个等待。
Chat 在同一次回应中按“等待 → 行动 → 等待”继续，建议每次最多 10 分钟；
这是会话指令上限，并非平台常驻保证。对局结束、返回大厅、用户停止或错误时结束。
已结束的 Chat 回应仍不能被该工具唤醒。真实普通 Chat 的双延迟事件验证通过，
完整线上牌局和后台持续运行仍须用户验收。

`interact_table` 复用原聊天、表情和道具规则：最多 10 个 Unicode 字符，
5 秒冷却，每局最多 3 次道具；当前已有番茄、鸡蛋、干杯，尚无鲜花道具。
它只操作 aevi，校验比赛与最新 cursor，拒绝重复/过期互动。桌面最近公开互动
随私有视图返回，事件 ID 用于避免重复回应；不会返回其他玩家手牌。

人格与记忆：官端玩法由实际调用工具的 ChatGPT 会话提供上下文，本模块不
复制 Gateway 的人格或长期记忆。如果该会话需要小家资料，先由现有 Gateway
在其权限边界内提供用户选定的人格与相关记忆摘录，交给会话作为背景；不要
给牌桌工具增加读取其他人的私聊/记忆能力。当前工具未实现记忆导入。

回滚：停止官端场、移除 `DOUDIZHU_MCP_PORT` 并重启，停止隧道客户端；
在 Platform 删除隧道/在 ChatGPT 移除应用可撤销连接。无需数据迁移。
Secure MCP Tunnel 还需要独立运行密钥，须在安全环境配置，不写入此仓库。
容器配置 `DOUDIZHU_TUNNEL_ID` 与 `CONTROL_PLANE_API_KEY` 后，由同一个
容器启动裁判和固定版本 0.0.14 隧道客户端。MCP 固定在 loopback 8899，隧道
健康检查在 loopback 8897。客户端二进制在构建期核对 SHA-256 并实际运行版本
检查；游戏子进程不继承隧道密钥，隧道子进程不继承 Gateway 牌桌密钥。
任一子进程退出会终止容器，由 Zeabur 现有重启策略处理。两个变量都不配置时
沿用原游戏启动方式；只配一个会明确失败。不要在电脑和服务器同时连接同一隧道。
云端回滚可移除这两个隧道变量并重启，或恢复旧部署 `9f5a649`；保留 `/data` 卷。
参考 [官方隧道说明](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)。

新增协议依赖为固定版本的官方 MCP SDK 与 Zod；不自制 JSON-RPC 协议。
`npm test` 包含两份永久检查：`scripts/test-official-player.js` 验证席位、规则、
重复/过期动作和生命周期；`scripts/test-doudizhu-mcp.js` 通过官方 SDK 客户端
验证实际 HTTP 握手、工具发现、隐私、参数约束与 Host/Origin/请求体边界。

## 直接运行

需要 Node.js 18 或更高版本。

```bash
npm install
npm start
```

打开 <http://127.0.0.1:8788/doudizhu/>。

本地策略适配器仍可供测试与旧 local 调用方使用；当前自由组桌 UI 需要配置所选牌友对应的 Gateway 或 MCP。裁判服务会在首次运行时创建 `data/doudizhu/`，保存积分、资料和牌局状态。

## 包含什么

- 54 张完整牌组、牌型识别、比较、发牌、叫分、过牌、炸弹/王炸、春天/反春天与跨局积分
- 15 秒回合时限，适配器异常时由裁判兜底，牌局不会卡死
- WebSocket 实时状态同步和 HTTP 操作接口
- 4 / 8 / 16 / 24 局家庭场，默认 4 局；固定一个真人座位，从三位 AI 中任选两位上桌
- 牌桌聊天、整场结束后按局整理的聊天记录与一键复制（支持摘要、整页展开、收起和退出）、13 个表情、番茄/鸡蛋/干杯互动道具、玩家资料与解散投票
- 四套桌布、完整图片素材、浏览器音效，以及 `normal.mp3` / `intense.mp3` 两首背景音乐
- 可替换的 stdin/stdout JSON 命令玩家协议

## 项目结构

## 接入自己的 AI

每个命令玩家从 stdin 接收一行 JSON，并向 stdout 输出一个 JSON 对象。最小输出示例：

```json
{"action":{"type":"play","cards":["S3"]},"say":"","emote":null,"prop":null}
```

首次运行后可修改 `data/doudizhu/players.json` 中对应玩家的 `command`、`cwd` 和 `env`。裁判会验证所有动作；超时、崩溃、非法 JSON 或非法出牌会重试一次，仍失败则自动代打。
